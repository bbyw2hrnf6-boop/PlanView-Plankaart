## Publishing procedure

1. Run `python3 tools/cloud_release.py status` from the canonical app. If unchanged, no deployment is needed. Run this procedure immediately after completing and validating an authorized app change, within that same task.
2. Read the installed Sites skill. Get the existing Site and verify its audience is still owner-only. Obtain a fresh source repository write credential with the native Sites tool; keep it in session memory, pass it to the source helper through hidden stdin, never save or print it.
3. Open/refresh the generated checkout using the Sites source helper. Use its exact opening result throughout. If cloud and local edits diverged, stop and report the conflict; never reset either history.
4. Run `python3 tools/cloud_release.py stage --checkout "/Users/uhorizon/Documents/ChatGPT/InteractiveMap/work/planview-cloud"` from the canonical app. Only the first migration uses `--force-initial`. The script validates JS/JSON/assets, mirrors browser assets into public/ and authored cloud/ server files into the existing Worker checkout, writes matching release.json to both copies, and rejects independently advanced cloud source.
5. Package and push with the native Sites source helper using the prior opening result, the Worker build command `["node", "/Users/uhorizon/.codex/plugins/cache/openai-curated-remote/sites/1.0.1/scripts/build-site.mjs"]` and an absolute tar.gz archive path. The helper owns the cloud source commit and push.
6. Publish that exact commit/archive with `save_version_and_deploy_private`. Poll only nonterminal deployments. On failure keep the returned saved version ID and follow the Sites repair workflow. Do not record a failed deployment as published.
7. After confirmed success, run `python3 tools/cloud_release.py record --fingerprint FINGERPRINT --commit SITE_COMMIT --deployment DEPLOYMENT_ID` with the exact staged fingerprint and returned identifiers. This saves a local receipt used to skip unchanged runs.

Synchronization happens in the same task as each authorized PlanView change: validate the completed change, push the exact cloud source, publish it and record the successful deployment before reporting completion. There is no scheduled task, periodic polling or background watcher. Do not recreate the removed cloud-sync automation. External edits and arbitrary local Git pushes are not automatically detected; publish them through this procedure when working on the change. Already published files remain hosted independently of the Mac. Existing open pages need reloading to use new files.
