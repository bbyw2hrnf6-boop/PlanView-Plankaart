# Permit history

Implemented 18 October 2026. This is a separate inspector tab for the selected parcel/location. It has no map layer, markers, area-search filters, rules-corpus integration or new API-key setting. Optional question answers use the existing AI connection only after explicit submission. EN: Permit history; DE: Bauanträge; NL: Bouwaanvragen.

## Sources and access

- [KOOP official-publications dataset](https://data.overheid.nl/dataset/officiele-bekendmakingen): public, CC0, daily updates. Public reading succeeded without authentication during implementation.
- [SRU 2.0 v1.4 documentation](https://data.overheid.nl/sites/default/files/dataset/d0cca537-44ea-48cf-9880-fa21e1a7058f/resources/HandleidingSRU2.0.pdf): use `https://repository.overheid.nl/sru`, collection `officielepublicaties`. The old local-publications collection is discontinued. The older `zoek.officielebekendmakingen.nl/sru/Search` endpoint is not used.
- [KOOP reuse and location guidance](https://www.koopoverheid.nl/voor-overheden/gemeenten-provincies-en-waterschappen/drop/meer-weten-over-drop/kennisbank-kwaliteit): publication geometry can be too broad or represent an effect area; it does not itself prove a parcel relationship.
- [PDOK BRK parcels](https://api.pdok.nl/kadaster/brk-kadastrale-kaart/ogc/v1/collections/perceel): resolve the actual polygon containing the selected point.
- [PDOK Locatieserver](https://api.pdok.nl/bzk/locatieserver/search/v3_1/ui/): address candidates are used as parcel evidence only if their source geometry lies within the resolved BRK polygon.

The public SRU service is intended for ongoing reuse, not a temporary trial. Its documentation invokes Fair Use without specifying a numerical per-minute/day entitlement. PlanView's internal budgets are conservative application limits, not a provider agreement or availability guarantee. CC0 on the catalogue/publication data does not make every third-party attachment or personal datum unrestricted. Only factual notice descriptions are summarized; originals are linked. Documents are not mass-downloaded or copied as a public archive. Explicit local questions may retrieve up to two officially linked PDFs, within fixed host, size, page and time limits. Temporary downloaded files are removed; bounded extraction caches remain in memory only.

## Retrieval and association

`POST /api/permits/point` accepts a strictly validated WGS84 `point`, an optional selected `parcelId` and an opaque point/date-bound pagination cursor. The browser opens this route only when the selected-location tab is activated. Text search and status/publication-year filters operate locally over already loaded procedures.

The shared engine in `cloud/lib/permits.mjs` runs in the cloud Worker and via `cloud/lib/permits-cli.mjs` from `local_permits.py` locally. The route is independent of AI/DSO credentials. Cloud access retains existing user authentication and same-origin checks; local access retains localhost same-origin JSON checks. Public-history retrieval never reads credentials. Optional question answering uses the existing local Codex/API connection or the signed-in cloud account’s encrypted AI key; public sources remain visible if AI is unavailable.

One bounded geographical SRU query combines `w.locatiepunt` with the production-supported `cd.afgeleideLocatiegebied` index, then is supplemented with parcel addresses established through PDOK. Live testing found that several documented address-specific indexes are unsupported by the production service, so supplements use supported full-text phrase queries. Exact association still requires matching structured source address fields, including house letter/addition, or an individual complete cadastral tuple. A point inside a parcel is only an uncertain mapped-location association. Mapped areas and lines are parsed from bounded WGS84/RD source geometry. Actual coverage of the selected point or intersection with the parcel appears directly in history, explicitly marked as an area association with unconfirmed parcel identity; broad areas get an additional warning. Effect areas are not promoted to the works location. The loaded history now has two views: This parcel (default, confirmed cadastral/address associations plus separately labelled title-address inferences) and Area & nearby (all uncertain area, mapped-location and nearby associations). Both show counts of loaded procedures, independent of the current text/status/year filters. Switching views is local, preserves those filters and does not change the separate document-question scope. An empty direct view does not establish that no application exists; further publication pages remain available. The working area index is shown in [KOOP’s map-module documentation](https://kaarten-demo.overheid.nl/doc.html); the older documented `w.locatiegebied` index returned an unsupported-index diagnostic during live validation. If parcel resolution is missing or ambiguous, no publication is upgraded to a confirmed parcel match. Historical address/parcel changes remain an explicit limitation.

Only records with building-related activity metadata or recognizable building-related titles are included. This can omit notices with vague titles and missing activity metadata; the result is never represented as every application ever submitted. Source document XML is fetched only from fixed, validated official-publication URLs. History retrieval keeps original attachments as links. Explicit local document search may follow selected official inspection pages to a linked PDF, with safe fixed-host validation at every redirect.

## Procedure chronology

Notices group only by an explicit case reference and authority identity; without an unambiguous case reference they stay separate. Addresses alone never merge applications. The interface displays each event's publication date separately from any explicit decision date. Last evidenced decision uses the known decision date, otherwise its publication date. A later deadline-extension notice does not erase an established decision. Draft, mixed grant/refusal, withdrawn application and revoked permit have distinct states; unclear or negated language stays unknown. Status is derived from published evidence, not confirmation of legal finality.

Summaries are concise Dutch activity/description passages from the notice, with a title fallback when no description is available. They are not AI legal assessments or a summary of an inaccessible full dossier. EN/DE/NL applies to interface labels, not an invented translation of official content.

## Questions within the Permit tab

`POST /api/permits/search` accepts only the selected point, optional parcel ID, plain question (at most 1,000 characters) and EN/NL/DE language. An explicit-submit form and examples follow the Rules interaction. A separate structured AI step interprets the question and translates its meaning into Dutch search concepts before location-bound retrieval. The server validates that plan and preserves user-supplied numbers and case references. It never accepts a client-provided search plan, evidence or URL. Without AI, available multilingual terms remain usable and interpretation is labelled unavailable. The existing local text/status/year filters remain a separate control for loaded history; no keystrokes trigger remote searches.

Retrieval is bounded to two pages / 50 candidates within 52 seconds, then ranks at most 12 source excerpts and keeps related procedural steps. This is not exhaustive text search across every historical permit. The model sees at most eight excerpts, each bounded to 6,000 characters, and must cite continuous exact original quotes. Server validation rejects unknown source IDs, changed quotes and numeric facts absent from the cited quotation, including dates supplied only in source metadata. Unavailable-body title fallbacks remain readable source cards but cannot ground an answer. It never fetches arbitrary user URLs or planning rules. The local server can enrich selected procedures with officially linked PDF decisions. Only supplied, successfully extracted pages can ground an answer. Refusal reasons are shown only when present in that evidence; unavailable decisions remain linked with an explicit limitation. The cloud source currently supports interpreted notice search and explicitly reports that attachments were not loaded; publication of this local enhancement remains deferred.

The UI shows the interpreted Dutch query, a direct answer followed by a short supporting summary, and source passages with safe text highlights. A claim links to its exact quoted passage. Search-term matches and verified quotations are distinct from proof of current building rights. When the answer is not established, the gap is stated directly instead of inventing a result.

Local PDFs are fetched only from server-retrieved official links on fixed HTTPS hosts: repository.overheid.nl, zoek.officielebekendmakingen.nl and open.rijkswaterstaat.nl. Every redirect is revalidated; no credentials, arbitrary hosts, query URLs, nested inspection-page crawl or unbounded download is allowed. Per question: at most two PDFs, 12 MiB each, 24 pages per PDF and 45 seconds including extraction. Native PDFKit reads text; Vision OCR handles scanned pages. OCR labels warn that words and numbers may be misrecognized. Limits and missing pages remain explicit. Completed pages stream progressively and are retained if a later OCR page reaches the deadline. Latest known decisions and newest notices are reserved before PDF excerpts fill the model evidence budget. At most six ranked PDF page excerpts plus notices enter the answer budget; extraction does not rewrite the notice-derived history status. `local_permit_documents.py` and `tools/permit_pdf_text.swift` are local-only. No new external PDF service, account or key is needed.

Public excerpts remain available without AI/DSO credentials and after an AI failure. Optional answers use the existing GPT-6 Luna High connection. An independent single-request lease and 12-question / five-minute application budget bound explicit questions. Cancellation and stale selections discard late answers; previously retrieved answers remain visible during another question. No question answers are saved to user cases or local storage.

## Limits and behavior

- 25 candidate publications per page, up to 1,000 candidate positions. The candidate total includes nonbuilding records; it is not an application count.
- Shared engine deadline: 45 seconds. Local CLI deadline: 60 seconds. Upstream responses, XML depth and element count are bounded; DTD/entity declarations are rejected.
- Up to three concurrent notice-document fetches. The engine's per-runtime budget is 90 lookups per five minutes, with a 60-second pause after an upstream 429. Local admission allows 40 uncached endpoint requests per five minutes; final-response cache hits do not consume this local budget. Cloud admission allows 40 endpoint requests per five minutes per account, including requests served from the source cache. These are application safeguards, not KOOP's stated quota.
- Public source text cache: five minutes, at most 12 MB per runtime. Local final-response cache: five minutes, at most 60 entries. Browser state is memory-only and capped at 12 selected locations. No background refresh or scheduled polling.
- Scope radius follows the current parcel, capped at 500 metres; large parcels, limited address candidates, missing documents, ambiguous geometry and truncation remain visible as coverage notes.
- `coverage.complete` is always false for historical scope. `partial` separately reports failures or truncated retrieval. Empty, partial and unavailable responses have distinct UI states. Pagination merges events and recomputes the last evidenced status/association across pages.
- Switching selection, cancellation and late responses cannot attach an old response to a new parcel. Previously retrieved results stay visible during refresh; filters and focus are preserved.

### Title-address cross-check · 19 October 2026
Loaded notice titles are automatically checked against PDOK address points inside the resolved BRK parcel, including when more publication pages are loaded. An exact street and complete house number (letter/addition included), with matching locality in the title or source metadata, can move a result from Area & nearby into This parcel. Such results retain `kind: title_address, certain: false` and an explicit inferred-link label, including in document answers. They never supersede a structured match or contradictory structured address metadata. Ambiguous number ranges/lists, neighbouring-location phrases and partial numbers are excluded. No AI or extra request is required; missing/ambiguous parcel identity and missing address candidates cannot produce this link. Existing query/page limits remain; this is not an exhaustive address search.
